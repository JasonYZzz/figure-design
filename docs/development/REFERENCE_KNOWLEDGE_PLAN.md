# 科研参考图库知识导航与检索优化实施计划

本计划面向 Figure Design 1.2.0 的本地参考图库。目标是逐张理解 161 张参考图，把可迁移的构图知识沉淀为可追溯、可检索、可用于实际排版的知识库。建议按“单图分析—跨图归纳—任务检索—构图验证—反馈更新”实施，继续使用现有 Python CLI、SQLite、内容来源绑定和质量检查链。

本轮完成实现审查、全库元数据及图片完整性核查、查询诊断，并结合前两次制图中已查看的参考图制定方案。全量原图逐张精读属于后续实施阶段。本文中的时间和验收阈值是规划值。

## 当前实现与问题证据

截至 2026 年 11 月 17 日，本地实际盘点结果如下。标签分布仅代表已有候选标注。

| 检查项 | 结果 | 对设计检索的影响 |
|---|---|---|
| 原图、索引、标注事件 | 各 161 条；全部原图 hash 匹配 | 原图和身份绑定可直接复用 |
| 审核状态 | 161 条 auto_proposed；人工金标 0 | 应区分模型分析覆盖率和人工确认率 |
| 观察描述 | 只有 9 种不同描述 | 描述粒度基本等同构图类别，无法区分同类图片 |
| 文字密度 | 161 条 unknown | 无法针对中文长标签筛选适用参考 |
| 素材标签 | 全部为空 | 图文混合需求缺少可检索特征 |
| 领域 | 生物医药 66、通用 36、社科 27、AI/计算机 15、地学 12、材料 5 | 领域筛选可保留，但需要逐图核实 |
| 构图 | 纵向阶段类 52、矩阵类 25、中心主体类 25、分支汇合类 22、多泳道类 20，其他 17 | 粗标签存在集中分布，不能直接作精细分类真值 |
| 许可 | 161 条 unknown | 参考用途与素材复用权限须分别记录 |

现有 `search()` 按空格分词，在四类标签及 observations 拼接文本中累计子串命中，人工审核记录加 0.25 分，同分按 hash ID 排序。没有中文查询归一化、分面过滤、拓扑匹配和同类结果去重。[实现](../../skills/figure-design/scripts/figure_catalog.py#L46)

按该匹配逻辑对只读索引进行查询诊断，得到以下结果。这组结果证明查询覆盖问题，尚不能作为有金标的精确率测量。

| 查询 | 命中数 | 观察 |
|---|---|---|
| 三条并行研究任务，汇合后进行验证 | 0 | 整句无法匹配 |
| 图文混合 生物医药 | 0 | 中文意图和英文标签之间没有映射 |
| 四年技术路线图 | 0 | 缺少面向真实请求的词汇 |
| 三条 并行 验证 | 52 | 命中通用描述中的“并行”，前五条全部只有 1 分 |
| biomedicine | 66 | 领域内全部同分 |
| top-overview-multi-lane biomedicine | 72 | 两词采用累计命中，实际接近并集召回 |

还有四处需要联动处理。

- `library.json` 明确记录已有分析来自 11 张缩略图联系表，且 `annual-stage-timeline` 同时表示一般纵向阶段。年份时间轴与纵向流程必须拆分。文件名或旧标签只能作为线索。[图库说明](../../skills/figure-design/assets/reference-library/library.json)
- 分类提示词要求区域、阅读顺序、置信度，但当前 schema 没有相应字段，`annotate()` 只接收旧字段。规范、保存和检索之间存在缺口。[提示词](../../skills/figure-design/references/prompts/reference-classifier.md)、[数据契约](../../skills/figure-design/schemas/reference-record.schema.json)
- `refs-review` 仅按宽高比抽样。人工审核需要覆盖不同领域、结构、密度、图文比例以及低置信度样本。[抽样实现](../../skills/figure-design/scripts/figure_catalog.py#L96)
- `plan` 当前根据关系类型和出度选母版，参考资料由 Codex 手动解释。检索知识需要进入研究简报和区域设计，才能改善成图。[候选构图](../../skills/figure-design/scripts/figure_plan.py#L132)

## 借鉴 LLM Wiki 的方式

Karpathy 的方案将源资料、持续维护的知识页与组织规则结合，并围绕 Ingest、Query、Lint 运作。本项目可把原图作为来源，把单图分析和跨图设计原则作为知识，把分类词表与来源约束作为规则。[原始设计](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

nashsu/llm_wiki 将分析和页面生成分成两阶段，并提供内容 hash 缓存、来源追踪、交叉链接和增量维护。它适合作为本项目“先观察、后归纳”的工程参照。[项目说明](https://github.com/nashsu/llm_wiki)

本轮另抽查了上游提交 `e08cfce65aad8b76b13546a081c1a8d4422b70c3` 的搜索实现，确认存在词法、可选向量以及图关联检索接口，并有向量请求失败后的降级路径。这里借鉴多路召回和可解释退化设计；具体排序参数需在本图库上评测。[搜索源码](https://github.com/nashsu/llm_wiki/blob/e08cfce65aad8b76b13546a081c1a8d4422b70c3/src-tauri/src/commands/search.rs)

建议首期以本地结构化记录、Markdown 导航和 SQLite 检索形成闭环。向量检索列为实验分支，触发条件是已有丰富单图描述和中文检索之后，留出测试仍存在明确的语义召回缺口。

## 知识库的数据组织

建议在现有 reference-library 下扩展以下目录，所有图片路径继续以库为基准解析。

```text
assets/reference-library/
  images/                       原始图片
  library.json                  数量、版本和覆盖率
  catalog.sqlite                现有记录、历史及新增索引
  taxonomy.yaml                 受控分类、中文名称、别名与定义
  analyses/<ref-id>.json         单图结构化分析的权威记录
  knowledge/
    purpose.md                  服务科研制图选择的目标与边界
    schema.md                   分析、归纳、引用和更新规则
    index.md                    导航入口
    references/<ref-id>.md       从单图记录生成的阅读页
    patterns/<pattern-id>.md     有来源的跨图设计原则
    tasks/<task-id>.md           按设计任务组织的导航
    log.md                      从事件记录生成的更新摘要
```

数据所有权需要明确。图片身份、路径与审核事件继续由现有 catalog 管理；新增单图视觉分析以版本化 JSON 为准，SQLite 中相应内容为可重建的查询投影。单图 Markdown 由 JSON 生成，修改通过结构化标注入口写回。跨图原则页保留稳定 claim ID、来源图片及区域 ID、适用条件和反例，作为经过审阅的综合知识。

这样，原图变更会使分析和下游原则失效，分类词表变更会触发映射检查，索引丢失可以重建。综合页的修改进入版本记录，禁止从派生索引反向覆盖来源分析。

每个分析记录绑定 `image_sha256`、schema 版本、分类词表版本、提示词版本、分析者及可获得的模型标识。未知模型版本显式保留 unknown。缓存键覆盖这些输入，避免仅检查图片 hash 而漏掉规则变更。

## 单图分析规范与分类方法

先建立 20 张试分析集，按宽高比、旧构图、领域及图文类型分层选择。每张实际打开原图，必要时放大局部。修订分类规则后，再完成余下 141 张，并对首批回填新规则。批次只是调度单位，每张图独立产出分析、证据和状态。

| 分析维度 | 记录内容 | 主要用途 |
|---|---|---|
| 研究表达目的 | 技术路线、机制、实验设计、比较、验证、系统架构 | 理解图要回答什么问题 |
| 关系拓扑 | 串行、并行、分支、汇合、反馈、对照及混合结构 | 匹配当前研究关系 |
| 空间组织 | 阅读方向、主次区域、列数、阶段数、主视觉位置 | 选择构图策略 |
| 信息容量 | 可辨文字块数量、文字占比估计、密度及不确定性 | 评估中文标签适配性 |
| 图文结合 | 插图所在区域、对象类别、插图与文字的对应关系 | 匹配图文版设计需求 |
| 视觉编码 | 颜色、边框、实虚线、字号层级的可观察用法 | 提取可复用表现规则 |
| 可迁移性 | 适用任务、需要改动的区域、拥挤风险、限制条件 | 生成具体设计建议 |
| 可核验性 | 区域坐标、观察、推断、疑点、来源 hash | 支持回看与纠错 |

采用多标签分面。领域是一个维度，构图与关系是独立维度。同一图片可以同时具有“横向三列、列内串行、底部验证”的结构。用 `temporal_axis` 区分明确时间标注、一般阶段和未知，旧 `annual-stage-timeline` 保留兼容映射并逐图重判。

区域采用归一化 bounds，记录父区域、角色、阅读次序、文本和插图对应关系。图内连线只在端点与方向可辨时记录，遮挡或模糊处标未知。dHash 用于发现相似图候选，构图相似性依靠区域结构和关系记录核实。

每项设计判断都附可查看依据。例如“这张图适合三组对照”须引用三块对应面板；“文字拥挤”须说明相关区域和观察条件。模型置信分只用于复核排序，不能解释为统计准确率。

单图卡固定回答五个问题。

1. 图在表达什么，读者按什么顺序阅读？
2. 哪些对象串行、并行、比较或反馈？
3. 哪个局部最值得迁移，适用什么研究任务？
4. 迁移到中文长标签或不同任务数量时，哪里需要改版？
5. 哪些部分看不清、容易误用或需要进一步核查？

完成标准为每张原图有独立观察、区域依据、设计适用说明与疑点清单。无法判断可以作为有效结果。全量分析覆盖率与人工审核比例分别统计，模型分析保持 auto_proposed。

## 从单图到设计知识导航

按三类问题建立入口，使检索能从研究意图进入。

| 导航入口 | 示例问题 | 应返回的内容 |
|---|---|---|
| 研究任务 | 四个年度如何衔接；三条研究支线如何汇合 | 对应结构原则、候选图与容量限制 |
| 设计问题 | 中文较长如何排；主路径与条件性验证如何区分 | 区域设计方法、实例及反例 |
| 视觉形式 | 图文混合、中心机制、横向泳道、分层递进 | 风格与构图实例，原图定位 |

每个原则页包含问题、适用条件、区域组织建议、可核验实例、限制及相邻模式。初期以至少两张独立参考图支持“跨图归纳”；只有一张支持时保留为单例。两图并不能证明普适性，需要明确适用范围。

根据本会话已查看的原图，可以先验证三个分析方向。`ref-029.png` 可提供图文配对的横向步骤组织；`ref-080.png` 可提供多列研究任务与底部验证组织；`ref-091.png` 可提供左侧阶段指示与主体流程的对齐。正式入库仍需要本阶段的独立分析卡和区域绑定。

建立 `illustrates`、`variant_of`、`contrasts_with` 等明确关系。任何连边必须有解释；共享领域标签用于筛选，相似拓扑才支持结构关联。生成的本地导航 HTML 可在现有 refs-review 基础上扩展，提供筛选、缩略图、单图说明及原图定位。

## 检索流程

建议使两类输入共用同一检索核心。自然语言查询用于人手检索，结构化 brief 用于制图工作流。现有 `--query` 保持可用，新增可选的 brief 与解释输出。

1. **解析需求。** 从用户文字或 research-brief 提取目的、任务数量、关系、阅读方向、文字容量及图文偏好。区分明确要求与推断偏好，保存归一化结果。
2. **多路召回。** 结合中英别名、描述文本和结构字段。首期采用中文术语表、英文词、中文字符二元组的分字段词法检索，适当提高短语权重。先检测 SQLite FTS5 可用性，再决定使用 FTS5 或小库内存评分。中文切分能力须有单独测试。
3. **应用约束。** 用户明确条件作为过滤项；领域相近、风格、来源审核状态等作为软排序因素。未知值保留 unknown 并解释，不能被悄悄当作满足要求。
4. **结构排序。** 优先目的、拓扑、任务数量和文字承载能力，再比较图文角色与视觉风格。排序分项完整返回，权重只在开发查询集调整。
5. **多样性选择。** 抑制精确重复和近似构图挤占名额，在相关候选中保留不同可行构图。最多一跳扩展原则页关联，避免热门节点无限放大。
6. **视觉复核。** Codex 对最终 3–5 张候选打开原图，核对适配性，选择最多两个主要构图。将适用区域、借鉴点、需修改点写入 research-brief。

检索结果应返回 `reference_id`、图片 hash、分析版本、命中字段、匹配理由、已知限制、可迁移区域、相关原则页和实际图片状态。所有解释从记录生成，避免没有证据的推荐用语。

对“图文混合、三项方法、底部条件验证”的查询，应明确匹配插图—文字配对、三列结构和条件分支表达。即便参考图属于其他学科，也可以给出结构迁移建议。图内的领域结论不能进入用户 FigureContent。

轻量包缺图时可继续检索文字知识并显示 missing，明确视觉复核尚待原图。候选文件异常在检索层可见，原件缺失或 hash 变化不能被当作已视觉核验。

## 与构图和反馈的衔接

新增知识的产出需要被实际设计使用。`research-brief` 增加设计检索需求、选图依据、原则来源及排除原因。`plan` 增加可选参考建议输入，将布局家族和区域比例作为建议，同时继续让 FigureContent 决定文字、研究对象和科学关系。

继承参考布局时，由 Codex 把当前任务映射到区域，原生字体度量和连接线预检判定是否可用。出现文本超容或无法路由时，记录具体布局失败原因，并转到另一候选。真实反馈应能回答“找得相关但文字装不下”与“领域相同但结构不适配”。

反馈记录保存 query、brief hash、候选、实际选用项、迁移改动、preflight 结果和用户实际反馈。记录引用用户文档的部分留在任务工作目录；共享图库只接收通用设计结论。用户验收与模型自检使用独立状态。

## 增量更新与可靠性

- 新图按 hash 获得新 ID；同内容新增路径继续使用别名。文件被替换时保留旧记录和事件，对新图重新分析。
- 图片移走或缺失时标记生命周期状态，防止陈旧记录继续作为可打开候选。历史记录仍可审计。
- 单图记录变动只使相关索引、单图页和引用它的原则页失效；记录依赖 hash，保留 stale 状态供重编译。
- 批次任务持久化 pending、running、completed、failed 状态。中断后可从成功记录继续，写入采用临时文件与原子替换，索引更新使用事务。
- 发布一代知识库时生成 manifest，检查记录、索引和导航的 generation ID 一致；未完成的新代不能替换已可用版本。
- Lint 检查未知分类、悬空链接、越界区域、来源 hash 不匹配、未定位的设计断言、失效页和重复原则。它验证形式一致性，图像语义另做抽审。
- 轻量包明确排除原图、缩略图、裁片、嵌图审阅页和私有任务日志。当前 pack 仅按原图目录排除的规则需要扩展到这些新产物。

现有 `annotate()` 会把未传入字段写成空列表，并直接更新审核状态。迁移时明确“全量替换”与“局部修改”的契约，新增分析采用独立版本和 expected hash 校验，保留旧 CLI 的既有语义，避免局部补充时清空旧标注或覆盖人工版本。

## 效果评估与发布门槛

先冻结 60 条查询，建议 30 条开发、30 条留出。覆盖中文自然句、英文标签、中英混合、拓扑约束、图文需求、跨领域迁移和库内无适配案例。语义相近查询放在同一侧，避免改写泄漏。参考图相关性按 0–3 级标注，并分别记录领域、拓扑、图文和容量匹配。

用旧检索、新描述加旧检索、新描述加新检索三组对照，拆开“知识更完整”和“排序更好”的贡献。加入多样性和可选向量时分别消融，统一 Top-K、图库和查询集。Recall 的判断须尽可能覆盖全库；只使用候选池标注时，报告候选池召回及未判定比例。

| 维度 | 建议初始门槛 | 测量方法 |
|---|---|---|
| 逐图覆盖 | 161/161 | 完整分析和明确未知均计入覆盖；失败独列 |
| 结构准确性 | 抽审关键字段一致率 ≥90% | 至少 30 张分层样本独立复核；公布各字段结果 |
| 检索相关性 | nDCG@5 比基线相对提高 ≥20% | 冻结留出查询，报告逐查询变化和置信区间 |
| 可用结果 | 有适配参考的查询 Hit@5 ≥90% | 至少一条相关性 ≥2 的候选；无适配查询另评 |
| 重复程度 | Top-5 近似构图冗余降低 ≥30% | 精确重复按 hash，近似重复按独立结构标注 |
| 原图追溯 | 来源与当前图像状态正确率 100% | hash、路径和分析版本自动检查 |
| 检索延迟 | 本地词法和结构检索 P95 ≤300 ms | 指定测试机器，区分冷启动、热查询与视觉复核耗时 |
| 成图效果 | 12 个固定 brief 配对比较 | 固定内容与资源预算，记录预检通过率、改版次数、耗时及盲评偏好 |

数值为验收目标，P0 后可基于基线确定修订，进入留出测试后冻结。旧基线为零的指标报告绝对改善，避免无意义的相对增幅。样本较少时报告不确定性，不能据单一胜率宣称普遍提升。

12 个 brief 至少包含 v20 的四年技术路线、v24 的图文方法与条件性验证，以及反馈结构、跨尺度机制、高密度中文、多组对照等不同任务。人工比较关注研究逻辑、可读性、图文对应和整体视觉层级，记录评价分歧。

必要回归包括旧 catalog 可读、中文不加空格查询、空查询全量枚举、reviewed-only 行为、missing/modified 图片、同 hash 别名、局部更新保护、重建可重复、增量中断恢复、原图及规则变更失效、包内私有图像排除。全量枚举供 pack 与 refs-review 调用，不能因新的 Top-K 去重逻辑漏掉记录。现有软件 benchmark 继续检验排版，新增检索评测独立报告。

## 建议执行起点

第一批提交完成 P0 的 schema、词表、可复现基线和 20 张实际分析卡，展示“同一构图类别内部如何区分”及三条中文查询的完整检索解释。确认字段足以支持设计决策后再完成全量分析，并保留版本迁移与覆盖清单。

本计划没有设定每张图均需人工确认后才可检索。模型分析可作为候选持续供设计使用，人工复核用于高价值样本、争议项及评测金标。已有图片许可状态继续沿用，图文效果的提升来自设计知识与已授权素材的合理组合。
