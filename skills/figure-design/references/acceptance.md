# 软件验收与科研交付边界

可运行功能以 [独立工作流程](standalone-workflow.md) 和 CLI `--help` 为准。

## 纯文字审阅

通过随包 Diagram Design 的自检和导出后，宿主实际打开 HTML 和 PNG，核对三项：

- **内容和来源**。读者能否从图中回答绘图前确定的核心问题。关键节点与箭头能否回到原文，交接物、关系方向、分支条件、对照和证据状态是否准确。
- **范围和取舍**。主图保留了影响理解的内容，记录省略的细节及理由、来源冲突和待确认项。新增文字应帮助读者理解职责、产出、关系或验证。
- **实际图面**。在目标使用尺寸核对字形、字号、文字重叠或越界、箭头端点和阅读顺序。版面需要修改时调整后重新导出。机器检查结果只覆盖所运行的工具。

在输出目录的 `quality-report.json` 补充 `review_record`，记录使用的图型及理由、主题或参考、用途及尺寸、关键节点或边与来源定位、内容取舍、实际预览结果和待确认项。逐项记录通过、需修订或未检查。沿用导出器的文件哈希、自动检查结果及 `review_required`。宿主核对来源或图面后，可在 `pending` 移除对应已完成的审阅项，用户验收由用户实际完成。

## 图文混合审阅

图文混合检查原文绑定、研究状态、必需实例和关键关系、实际文字和字体、文字越界/重叠、连线避障、素材权限 metadata 和输出 hash。任何机器错误阻断正式导出。数学、字形或路由不支持时须报错。

机器门禁通过后的状态仍是 review_required：宿主 Agent 审查语义与画面，用户真正验收后才能使用 hash 绑定的接受记录。人类标签金标、资产版权真实性、学科专家盲评、线上供应商实际计费能力是外部验证，不能由脚本或模型自签。

30 图审校入口是 refs-review 生成的 HTML 和 annotations.json。填写真实审核者、分类、观察、推断及 attestation，再 refs-annotate；未完成时保持 auto_proposed，不阻止把候选当作待核对设计线索，但禁止宣称为金标。

图文混合的 draft ZIP 可供审阅，final ZIP 要求该 render_hash 的完整人类接受记录。旧图与未知模型请求不自动覆盖或重提。

参考驱动成图须按 [整图迁移审阅](reference-design.md) 查看最终 PNG。记录目标尺寸、各特征实际所在和配色比较。自动检查包含页脚和连接标签的边界框；宿主审阅负责判断整图层级、风格和布局取舍。
